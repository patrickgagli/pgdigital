Le backlog produit est la liste ordonnée et évolutive des besoins, améliorations et problèmes à traiter. Il est affiné régulièrement par le Product Owner avec les parties prenantes et l’équipe. Les tâches de réalisation sont suivies dans le backlog de sprint; les éléments ne sont considérés terminés que lorsque les critères d’acceptation et la définition de fini sont respectés.

## 3. Conventions du backlog

### Types d’éléments

| Type | Utilisation |
| --- | --- |
| User story | Besoin formulé du point de vue d’un utilisateur ou bénéficiaire. |
| Story technique | Travail technique nécessaire au produit, même sans utilisateur direct. |
| Bug | Comportement du produit qui ne respecte pas le comportement attendu. |
| Défaut | Problème de qualité ou écart constaté à corriger. |

### États de workflow

Adapter les états aux règles de l’équipe. L’état décrit le workflow de l’élément; il ne remplace ni la priorité ni l’estimation.

| État | Signification dans ce projet |
| --- | --- |
| À valider | Besoin à clarifier ou à faire confirmer. |
| Créé | Élément enregistré dans le backlog, pas nécessairement prêt. |
| Accepté | Besoin compris et accepté dans le périmètre produit. |
| Estimé | Effort évalué par l’équipe. |
| Planifié | Élément sélectionné pour une période ou un sprint. |
| En cours | Travail commencé. |
| Fini | Critères d’acceptation satisfaits et définition de fini respectée. |
